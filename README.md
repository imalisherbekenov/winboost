# WinBoost 4.0

Локальное приложение для анализа и настройки Windows 10/11 x64, с проверкой действий перед применением и снимками настроек. Новый сайт и программа используют общую палитру Obsidian: почти чёрные поверхности и акцент шампань (#C9B68F).

## Запуск

Готовая программа: `dist/WinBoost-4.0.exe`. Обычный запуск запрашивает права администратора через UAC. На первом запуске создаётся первичный снимок; если его создание не удалось, причина появляется в журнале. Перед каждой сессией отдельно сохраняются затрагиваемые настройки. Ошибка создания этого снимка останавливает применение.

EXE собран локально и не подписан цифровым сертификатом. Сайт: https://winboost.vercel.app. Файл загрузки хранится в `site/public/downloads/WinBoost-4.0.exe`; рядом опубликована контрольная сумма SHA256. Отдельный GitHub Release для 4.0 не создавался.

## Что нового

- Обзор системы с показателями CPU, памяти и диска, обновление каждые 2 секунды.
- Три сценария: повседневный, игровой, приватность. Только обратимые действия низкого риска.
- Каталог из 10 модулей и 55 действий: поиск, фильтрация риска, выбор и проверка набора.
- Экспорт анализа в JSON и автоматические отчёты выполненных сессий.
- Необратимые действия сняты с выбора по умолчанию и требуют отдельного подтверждения.
- Остановка после текущего действия с сохранением результатов и снимка.
- Более точный учёт ошибок, атомарная запись снимков изменений, подтверждение восстановления.
- Новый сайт с CSS 3D, анимацией переходов и интерактивным демо.

Полный список: [CHANGELOG.md](CHANGELOG.md).

## Разработка приложения

```powershell
cd app
python -m pip install -r requirements.txt
python WinBoostGUI.py
python -m pytest tests -q
```

Сборка EXE и копирование в каталог загрузок сайта:

```powershell
cd app
python -m pip install pyinstaller
powershell -ExecutionPolicy Bypass -File build.ps1
```

Версия читается из `APP_TITLE` в `WinBoostGUI.py`. Сборка не удаляет старые дистрибутивы. Готовый файл появляется в `dist/` в корне проекта и в `site/public/downloads/`.

Снимки экранов без запуска оптимизаций:

```powershell
python WinBoostGUI.py --capture-all theme_previews/v4
```

Режим захвата анализа читает реальную конфигурацию компьютера. Скриншоты могут содержать сведения о вашем оборудовании.

## Сайт

```powershell
cd site
npm ci
npm run dev
```

Проверка production-сборки:

```powershell
npm run build
npm start
```

Сайт откроется на http://127.0.0.1:4173. `PORT` меняет порт. Статический экспорт находится в `site/out/`. Сначала соберите EXE, затем сайт, чтобы в экспорт попал актуальный файл загрузки.

Сайт использует Next.js 15, React 19 и Tailwind 4. Анимации реализованы на CSS, Pointer Events и IntersectionObserver; поддерживается reduced motion. Демо содержит явно обозначенные примерные данные и никогда не меняет настройки компьютера.

## Данные и откат

`%APPDATA%/WinBoost/backups/` — снимки, включая первичный `baseline.json`.
`%APPDATA%/WinBoost/reports/` — JSON-отчёты сессий.
Журнал находится в локальном каталоге WinBoost, путь задаёт `modules/logsetup.py`.

Снимок сохраняет реестр, службы, задачи планировщика, активный план питания, DNS и сведения об удаляемых UWP-пакетах. Файлы и удалённые приложения автоматически не восстанавливаются. Остановка не отменяет уже выполненные изменения. Для отката выберите снимок, изучите предупреждение и подтвердите восстановление.

Системные команды выполняются через `modules/winshell.py` с корректной Windows-кодировкой. Новое действие обязано описывать `effects`; иначе его изменения не попадут в снимок.

## Проверки

Тесты движка используют подменённые операции. Проверки интерфейса создают настоящий контекст Dear PyGui без изменения Windows. Интеграционный тест отдельного ключа HKCU пропускается, если среда запрещает запись.

Реальное применение всех системных твиков, откат после перезагрузки и замеры FPS не выполнялись. Для проверки таких сценариев нужна отдельная тестовая Windows-машина.
